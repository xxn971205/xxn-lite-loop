# 巡检会话与飞书提醒

## L2/L3 小巡检

先跑 `node <skill>/scripts/loopctl.mjs tick --req <slug> --role patrol --apply`，无输出即结束本轮。看到 `facts-error` 时说明读取或核验失败的来源。遇到 `needsLlm: false` 只记录脚本回执。其余动作按下文处理。

小巡检是每位开发者自己的进度和裁决窗口，范围以本人的台账和相关变更为准。

## L3 大巡检

先跑 `node <skill>/scripts/loopctl.mjs tick --req <slug> --role lead-patrol --apply`，无输出即结束本轮。看到 `facts-error` 时说明读取或核验失败的来源。遇到 `needsLlm: false` 只记录脚本回执。其余动作按下文处理。

大巡检在主研发机器上看总台账和各槽位。工作日全量巡检和到点日报由本角色的 `tick` 触发。机械提醒、评论去重、发送时段和失败重试由 `tick` 与 `notify` 执行。非工作时段记录推迟的发现并刷新心跳，超时未裁决的紧急阻断仍留评论。进入工作时段后，复核推迟的发现，为仍有效的事项写评论、入队和汇报。

## 按任务处理

- `patrol-review` 附 `ranges`（台账变动、PR/MR diff 引用、新配置评论、设计链接、契约变化）。按范围读相关内容。`full: true` 时按关联记录做全量检查。判断是否偏离业务流程、有无该升级的事被本地消化、台账是否混入设计笔记、个人规矩是否绕开门禁，以及设计文档与契约是否一致。发现问题时发【纠偏】，写清证据、影响和动作。巡检会话只写评论。
- `user-report`、首报和用户主动问进度时，按下方的三句话回答。 [用户窗口](#用户窗口)
- `notify-awaiting-confirm` 时把待发内容和目标给本人看。对外接口或消息契约调整用 `notify enqueue --req <slug> --kind contract-sync --dedup <变更键> --text <文字>`。说明变更原因、受影响入口和接入方、适配动作、版本及生效状态，并附契约和裁决链接。本人确认后执行 `notify confirm --req <slug> --id <事件ID>`，由出站队列发送。
- 通知未收到成功回执时以队列状态和 `user-report` 为准。`notify flush` 按当前群和成员映射核对目标、送达、时段与重试上限。普通提醒在无目标或静默时入队即抑制，已有待发提醒最多保留 24 个工作小时。投递目标和时段恢复后，仍成立的提醒会以新事件入队一次。日报只发送工作时区当天的最新一份。契约同步和须确认的提醒一直保留，确认后等投递目标和工作时段就绪再发送。达到上限后在会话内提示核对，保留原事件与去重键。

## 用户窗口

先执行 `node <skill>/scripts/loopctl.mjs status --req <slug> --live --json`，读取台账、变更和本机唤醒记录。进度和需本人处理的事以 `live.forgeFacts` 为准。读取失败影响哪一句，就在那一句写清能核实到哪，待办暂未核实时说明还在核对。

1. **现在到哪了。** 「已完成 {子任务进度}，{合入进度}，现在在做{台账里的当前事项}。」句后附台账或当前变更链接。
2. **等你做什么。** 「请你{要确认、裁决或合入的具体事项}。」确实没有时说「没有要你处理的事。」句后附原事项链接，没有待办时附台账链接。
3. **最近一次醒来。** 「本机最近一次是{角色}在{时间}醒来，{做了什么}。」从 `run.recentTicks` 取时间最新的实跑记录，时间用本地 `HH:mm`，跨天加日期。按 `kind` 和 `code` 查登记表，无动作时说「这次没有新动作」。优先附 `live.scriptComments` 中对应的评论或动作里的事项链接，只有心跳时附该角色的台账链接。 [动作登记表](../scripts/lib/action-messages.mjs)

每句先说业务或人做了什么，再给能核对的链接。只有需要查证时才把内部代号放在链接后的括号里。若无唤醒记录或链接，直接说明缺了哪条记录，附目前可核对的台账链接。

- 用户明确给出裁决时，在对应台账、升级串或 PR/MR 用 `forge.mjs reply --kind issue|change --forge <forge> --repo <repo> --id <编号> --reply-to <原评论ID> --body <签名及【裁决】正文>` 留记录。写清执行人和解除条件。回传评论链接，按影响转达给负责会话。用户提问或犹豫时可对照证据解释，请他决定。
- 用户说「往 XX 群推送」时，执行 `loopctl.mjs notify bind --req <slug> --chat '<群名或 chat_id>'`。同名群将列候选，请用户选定再用 `chat_id` 执行。机器人不在群时请人在群设置里添加发送通知的机器人。只采用命令验证的成员匹配，对不上就原样告诉用户。
- 用户说「别发群了」时用 `notify unbind --req <slug>`。说「暂停飞书推送」「恢复飞书推送」时分别用 `notify mute`、`notify unmute`。绑定和静默独立设置。只改本次需求为默认。用户明确要给后续需求设工程默认时加 `--scope project`。成功后给出台账【配置变更】记录，L3 绑定本次需求的群时看总台账。L2 可配私人提醒或绑定群，日报由 L3 大巡检投递。

## 跨会话转达

先在原串留证。正在执行的动作会因强纠偏、已确认裁决或停开决定而出错时才插入（`steer`），接收者在下个关键操作前重读原串。目标确实空闲且具体依赖解除时唤醒。只影响后续工作时入队（`queue`）一次，带结论、下一步与原链接。普通进度或机械回执留 Git 记录即可。无法安全投递时等下次正常唤醒。
