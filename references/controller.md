# 主控入口：路由表、唤醒判定与断点续接

本文件供各槽位主控（L1/L2 单人主控、L3 主研发主控与协作者主控）每次唤醒按需读取。**主控绝不亲自写代码，也不承担长篇需求讨论（聊控分离）。**

## 一、固定路由表（按需读最小集合，不一次读全部）

| 阶段 / 状态 / 触发 | 本轮必读 | 动作 |
| --- | --- | --- |
| **每次唤醒必读** | 本文件、本槽位台账正文；台账与本人 PR/MR 上尚无「已执行」或「不执行：理由」回复的【纠偏】【配置变更】【交接】【提醒】【裁决】【基线变更】【设计变更】评论；L3 另读总台账第 1 节当前阶段行与第 4 节契约版本及「本次临时规范」行（仅数行） | 先核身份与锁，再清评论、对账、按状态推进 |
| 外部主设计文档变更（子 Issue 出现【设计变更】） | 该【设计变更】评论与对应设计文档节 | 更新本子 Issue 五项；影响进行中的 PR/MR 时停在当前步骤请本人确认 |
| 首次启动 / 加入 L3 / 升档 | `lifecycle.md`、`tiers.md` | 走初始化或升档确认单，常规唤醒不重读 |
| P0 需求澄清 / P1 方案设计 | 本次需求文档、总台账 | 阻断疑问交本人（L1/L2）或主研发（L3）裁决 |
| P2 地基与契约（L3） | `templates.md`（第六节「子 Issue 讨论五项模板」）、契约与归属表 | 补齐本槽位业务级五项并汇总确认；地基 PR/MR 打「待终审」时协作者派拆分角色核契约 |
| P3 开发 · 未开始 | `templates.md`（第六节「子 Issue 讨论五项模板」） | 当前子 Issue 细化到代码层并拆 1–3 个可独立验收 PR/MR，停在固定确认点请本人确认 |
| P3 开发 · 进行中 | 本文件第四节「派活边界与确认点」、本 PR/MR 涉及契约与子 Issue | 异步派开发/自审，不亲自写代码；派出即写「已派 角色｜任务｜等结果」并结束本轮 |
| 待确认 | 本文件第四节「派活边界与确认点」 | 等本人回复，绝不越过固定确认点 |
| 待裁决 / 阻断 | 本文件第五节「疑问、阻断、缺陷优先路由与切换交接」、对应升级串 | 停被阻断点，禁做临时绕行；先推进同 Issue 无依赖 PR/MR 或临时切子 Issue |
| 待终审 / 终审中 | `review-and-dispatch.md` | 对账终审结论与超时（L1/L2 由主控直接派新终审会话；L3 交主研发调度处理） |
| 需修改 | 有效终审结论 | 抄必改项，派开发在原分支追加提交并逐条回复，换回「待终审」 |
| 待合并 / 已合入 | `review-and-dispatch.md`、本文件第五节 | 核实实际合入；非 bug 业务 Issue 全 PR/MR 合入后关闭并计划交接 |
| 暂停或非工作时段 | 本文件第五节 | 非工作时段仅更新最近唤醒后退出；暂停需「请求开工」恢复 |
| 缺陷优先路由（名下未关 bug） | 本文件第五节 | 当前 PR/MR 步骤完成后优先修复，不换主控会话 |
| 收到【基线变更】或基线更新 | `forge.mjs baseline-check` | 先 fetch 涉及子仓核对最新远端 SHA（fetch 失败必须停下不得假报对齐），复核受影响设计与分支再继续 |
| 收尾拆架 | `lifecycle.md`（第五节「收尾拆架」） | 两步法运行 `loopctl.mjs teardown` 预检 → 外部清理 → `--finalize` 核验归档 |

## 二、唤醒判定表（由 `loopctl.mjs wake-decision` 同口径校验）

适用定时唤醒（参数见 `tiers.md`）。「有依据」指存在交给自己的【交接】，或在工作时段由巡检判定失联/卡住的【提醒】评论。

| 标识是否自己 | 本轮状态 | 本人明确「接管/继续」 | 有接任依据 | 唯一动作 |
| --- | --- | --- | --- | --- |
| 是 | 空闲 | 任意 | 任意 | **开始本轮**：写「本轮：执行中」、开始时间、最近唤醒；对账推进；结束改空闲 |
| 是 | 执行中 | 否 | 任意 | **原主控执行中判定**：未满 `stuckHours`（2h）仅刷新最近唤醒退出；满 2h 重写执行中并发【恢复】续接 |
| 是 | 执行中 | 是 | 任意 | **先确认上一轮已停**：问本人确认停下后按断点重开并发【恢复】 |
| 否 | 任意 | 是 | 任意 | **主动接任**：接管前本人先关旧会话；登记第 N+1 任、发【交接】、自建本会话定时任务（先停旧同名任务） |
| 否 | 任意 | 否 | 是 | **按依据接任**：登记第 N+1 任、发【交接】/【恢复】、自建定时任务；遵守接任首轮边界 |
| 否 | 任意 | 否 | 否 | **退出非现任会话**：停用本会话定时任务并提示「已被第 N 任接替」 |

- **主动唤醒补充**：本人单纯问进度时只读四项回答，不新开轮次；其他手动唤醒原主控且本轮执行中，按「先确认上一轮已停」处理，不得并行开轮。
- **接任首轮边界**：无交给自己的【交接】而接任时，**首轮只写标识、发【恢复】/【交接】并对账，禁止 push、建 PR/MR、改标签**，下一轮再正常推进。

## 三、写前校验、先记后做与断点续接

1. **写前校验**：每次写台账、push、建 PR/MR、改标签前，必先读台账第 1 节主控标识并与本会话标识核对；非自己或缺少双方会话标识时，立即中止全量写操作（仅允许心跳刷新或接任写入自身标识当次豁免），确认已被接替则自停定时任务。
2. **先记后做**：执行 push、建 PR/MR、改标签等外部写操作前先在台账记「准备做 X」，成功后再改「已完成 X」。
3. **事实对账**：每次唤醒先以 Forge 实际提交、PR/MR、标签、Issue 状态为准对账；台账与实际不一致时以实际为准修正并发【恢复】。
4. **待处理评论**：按顺序处理未回复评论，处理后在原评论回复「已执行」；若主控认为【纠偏】有误，回复「不执行：理由」并列台账第 2 节交本人裁决，避免主控与巡检循环互怼。
5. **多仓基线对齐**：分析、细化或派开发前，对本次勾选的全部子仓执行 `git fetch` 并记录实际基线 SHA；收到【基线变更】对齐后在原评论回执已核实的合入提交与基线 SHA。

## 四、派活边界与确认点

| 角色 | 职责与交付 | 严禁越界 |
| --- | --- | --- |
| **拆分（Planner）** | 现状调研、方案细化、拆 1–3 个可独立验收 PR/MR、L3 地基契约核对 | 不改台账正文 |
| **开发（Coder）** | 写代码、按工程 `verification` 配置跑编译/单测/实测、解 rebase 冲突、写 PR/MR 描述草稿 | 不改计划外代码、不做顺手重构、不加无入口防御代码 |
| **自审（Self-Reviewer）** | 优先与开发跨厂商模型，按审查必改边界预检 diff | 不替代终审、无合并权 |
| **主控（Controller）** | 核验开发结果与归属、push、建 PR/MR、改标签、写台账 | **绝不亲自写代码**；异步派活后立即结束本轮不干等 |

**固定确认点（不可关闭）**：初始化/升档确认单、P2 五项汇总（L3）、P3 每个业务子 Issue 细化后开发前、需求偏差或疑问、累计打回 `k≥2` 全量重审裁决、计划/异常交接。可选确认点（提交前本人先看、送审前先看、完 Issue 切换前确认、拆分计划确认）按本机偏好配置。

## 五、疑问、阻断、缺陷优先路由与切换交接

- **疑问与阻断**：L1/L2 疑问交本人裁决；L3 命中跨台账硬条件（改契约、改删非本人/热点文件已有内容、归属争议/阻断他人/超期依赖、冲突定稿、需例外批准）在升级 Issue 开独立串，被阻断子 Issue 打「阻断」标。**严禁 AI 做临时方案绕过阻断**；先推进同 Issue 无依赖 PR/MR，实在无事才临时切换下一个已细化子 Issue（不换主控会话，原 Issue 记第 4 节）。
- **工作时段、临时加班与下班全停**：非工作时段判身份后仅更新最近唤醒退出（初始化首报与接管除外）。本人临时加班可口头开启「全天办理」；说「暂停」时仅收尾当前主控步骤并改「暂停（原：某状态）」；说「下班 / 全部暂停」时自动结束临时全天时段，**成组暂停本人名下全部循环定时任务**（主控、小巡检、大巡检、调度、日报），原样保留任务 ID、绑定与频率；待本人说「开工」按原配置恢复。在非主控会话说停/开则发【配置变更】评论并按通知法则传达。
- **缺陷优先路由**：当前 PR/MR 步骤完成后，优先处理指派本人且未关闭、无「已合入基线」评论（或最新该评论后出现「复测不通过」）的 `bug` 子 Issue。修 bug 不换会话、追加到台账第 3 节；合入需求基线后评论「已合入基线｜PR/MR 链接｜待部署验证后复测」并移出第 3 节；由发现人或主研发复测通过后关闭。
- **切换 Issue 与计划交接**：非 bug 业务子 Issue 全部 PR/MR 合入后关闭；L2/L3 每完成一个业务子 Issue 一律执行计划交接换新主控会话（见 `lifecycle.md`）。
