# 主控

定时唤醒先跑 `node <skill>/scripts/loopctl.mjs tick --req <slug> --role controller --apply --session <本会话标识>`，无输出即结束本轮。收到 `SUPERSEDED` 就删除本会话的主控定时任务并结束。看到 `facts-error` 时说明哪个来源读取或校验失败，本轮以已核实的回执为准，停止依赖失败数据的推进。遇到 `needsLlm: false` 只记录脚本回执。

主控按动作给出的引用对账、安排开发和验证。L2/L3 的进度、疑问和裁决在巡检窗口处理。L1 用户问进度时，跑 `status --req <slug> --live --json`，各用一句说清进度、待办和最近唤醒，逐句附链接。 [用户窗口](patrol-and-notify.md#用户窗口)

用户明确说接管、开工、暂停或拆架时按对应人工入口办理。

## 按动作续接

- `controller` 给出本轮原因与记录。核对现任，读自己的台账与引用。L3 再核总台账的当前阶段、契约版本和本次临时规范。
- `review-dispatch` 交给 [终审入口](review-and-dispatch.md)。L1/L2 主控派独立终审，主控的 `tick` 负责分流。L3 的派审和分流归主研发调度。
- `tick` 负责定时轮的身份判定、开工时段、心跳、卡住自愈和可推进项检查。宿主主动接管前用 `wake-decision` 核对身份。
- 空闲且有可推进项时，每次定时唤醒都可开轮。等本人确认、裁决或其他槽位时，同一事项每隔 `thresholds.controllerReminderHours` 个工作小时提醒，默认 2 个工作小时。
- 对齐本轮真实状态后，把现任主控的「本轮」记为「执行中」并写开始时间。先记下一步「准备做 X」，外部动作成功后记「已完成 X」，本轮完成即记「空闲」。遇到外部动作中断，先对账并用【恢复】说明已做、待做。
- 每次外部写操作前核对当前台账第 1 节的主控标识。写正文用 `forge.mjs issue-update --expect-owner <本会话标识>`。确认已被接替就停写并停自己的任务。用户要求接管时先确认旧轮已停。没有指向自己的【交接】时，接任首轮只登记新标识、发评论和对账，下一轮再 push、建单或改标签。
- 处理评论后用 `forge.mjs reply --kind issue|change --forge <forge> --repo <repo> --id <编号> --reply-to <原评论ID> --body <签名及回执>` 写「已执行」或「不执行」并说明原因。认为纠偏有误时，把争议列为待本人处理。收到【基线变更】先运行 `forge.mjs baseline-check`，对齐后在回执里写基线 SHA。

## 主控怎么派活

1. 按阶段和 [交付单元模板](templates.md#业务子-issue-五项) 推进。L3 地基送审时，安排拆分角色核契约和文件归属。外部设计有定稿变更时更新子 Issue 五项。影响正在开发的变更单就停在当前步骤请人确认。
2. 派拆分角色调研并切可验收的变更，派开发角色实现并按工程配置验证，按需派跨模型自审。派出前用 `loopctl.mjs brief --run <run.json>` 生成任务说明。多仓下编号无法唯一定位时，用 `owner/repo#编号` 或完整 URL。`brief` 会 fetch 并更新对应的 `origin/*` 基线引用。派出后在台账记角色、任务和要等的结果，再结束本轮。
3. 主控核验结果、提交并建变更单。确认点包括初始化与升档、L3 五项汇总、每个 L2/L3 业务子 Issue 细化后开发前、需求偏差或疑问、全量重审裁决和交接。自选确认点以本机配置为准。按 `config-resolve` 返回的生效协作规矩派活。

## 阻断、缺陷和交接

- L1/L2 疑问列入台账交本人。L3 涉及改契约、改删他人或热点文件已有内容、跨槽位依赖阻断、定稿冲突或例外时，开 [升级串](templates.md#l3-升级串)，给被阻断的子 Issue 打「阻断」。先推进不依赖该裁决的已确认工作。
- `tick` 发现可处理的缺陷时，做完当前变更单步骤后优先修复。合入基线后在缺陷 Issue 记「已合入基线」、变更单和待验证事项，从当前工作清单移出。由发现人或主研发复测通过后关闭。修缺陷沿用当前主控。
- 「暂停」时收完当前步骤并记原状态。「下班」「全部暂停」时也结束临时加班时段，成组暂停本人名下定时任务。「开工」时恢复原状态、任务 ID 与周期。用户在其他会话作出停开决定时先发【配置变更】，按 [跨会话转达](patrol-and-notify.md#跨会话转达) 通知。
- 全部变更单实际合入后关闭业务子 Issue。L2/L3 本槽位还有未完成的业务子 Issue 时按 [计划交接](lifecycle.md#计划交接) 换新主控。收到 `acceptance-dispatch` 时按 [出口验收](lifecycle.md#出口验收) 派活。收尾按 [两步拆架](lifecycle.md#两步拆架) 办理。
