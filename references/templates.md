# 标准模板集（确认单、台账、五项、升级串与评论签名）

所有 AI 评论首行强制固定签名，过程记录只追加评论不改旧评论，台账正文只保留当前快照（L2/L3 限 80 行内一屏读完）。

## 一、AI 评论首行签名与前缀

```text
角色 ｜ 槽位 ｜ 会话标识
【类型】正文内容
```

常用前缀：`【裁决】` `【纠偏】` `【交接】` `【恢复】` `【配置变更】` `【提醒】` `【基线变更】`。专用格式（升级首条、派终审、自动合并、bug 合入与复测、修改回复）可免前缀，但首行签名必写。

## 二、一句话启动确认单（6 行极简版，按档位裁剪）

```text
【xxn-lite-loop 初始化确认单】
1. 需求与档位：<req-slug> ｜ 档位：L1 / L2 / L3 ｜ 起跳阶段：P0 / P1 / P2 / P3
2. 工程组与基线：Forge=<gitlab|github> ｜ 核心仓=<hubRepo> ｜ 关联仓=<linkedRepos 或 无> ｜ 基线=<branch> ｜ 合并=<低风险自动合并 / 全人工合并>
3. 验证策略：mode=<isolated-build|local-test|hybrid> ｜ 命令=<校验命令>
4. 角色模型：主控=<m> ｜ 开发=<m> ｜ 自审=<m/关> ｜ 终审=<m> ｜ 巡检=<m/关>
5. 节奏与确认点：定时=<关 / 主控Nm+静音巡检Mm / 完整L3> ｜ 工作时段=<HH:MM-HH:MM TZ> ｜ 确认点=<固定项 + 已选可选项> ｜ 通知=<仅会话 / 群ID(限配置时段@)>
6. 收尾约定：业务仓库零规范残留，合入后按两步 teardown（预检清单 → 核验清理后归档）收尾。
请回复「确认」启动，或直接指出要改的一项。
```

## 2. 当前任务（简版范围与验收）

无

## 四、L2 主台账 / L3 小台账 5 节固定模板（≤ 80 行）

L2 标题：`【台账】<需求名称>`；L3 标题：`【小台账】<槽位>-<用户名>`

```markdown
## 1. 基本信息（当前状态）
档位：<L2/L3> ｜ 阶段：<P0-P4> ｜ 当前 Issue：<链接> ｜ 状态：<枚举 / 暂停（原：某状态）> ｜ 基于契约：<vN / 无>
当前步骤：<准备做 / 已完成 X>
主控：第 N 任 ｜ <会话标识> ｜ <环境> ｜ <接任时间>
本轮：<执行中（开始 MM-DD HH:MM） / 空闲>
最近唤醒：<MM-DD HH:MM>
依赖：<槽位/Issue/外部系统 ｜ 预计可用 MM-DD / 无>

## 2. 需本人处理
- [待确认] 一句话 ｜ 原因 ｜ 建议

## 3. 当前进行中（当前 Issue 的变更单计划）
| 变更单 | 内容一句话 | 状态 | 链接 |
| --- | --- | --- | --- |
| 1 | …… | 未开始 | 无 |

## 4. 近期完成与挂起（风险与阻断）
无

## 5. 流程提醒与规则引用（个人配置）
模型：主控 / 拆分 / 开发 / 自审 / 小巡检（L3 主研发另列终审与大巡检）
自审：是/否 ｜ 可选确认点：…… ｜ 巡检频率：…… ｜ 工作时段：…… ｜ 汇报方式：……
```

## 五、L3 总台账 5 节固定模板

标题：`【总台账】<需求名称>`

```markdown
## 1. 整体状态
当前阶段：<P0-P4> ｜ 下一节点：<阶段/目标与条件>
整体进度：Issue 已完成 N/M ｜ PR/MR 已合入 N/M
整体风险：<一句话 / 无>
全量审阅变更单：<各参与仓 Draft PR/MR 链接>

## 2. 待主研发处理（只列未关闭项）
- [待裁决] 升级-槽位-NNN ｜ 链接
- [待终审] 跨仓筛选链接
- [待合并] 跨仓筛选链接
- 【提醒】未解决提醒 ｜ 链接

## 3. 各开发者
| 槽位 | 用户名 | 负责范围 | 依赖（照抄小台账并标来源） | 小台账链接 |
| --- | --- | --- | --- | --- |

## 4. 契约、归属与本次临时规范
契约版本：vN（状态） → 链接
文件归属表 → 链接
本次临时规范（仅本次需求生效，拆架即止）：无 / 条目与依据链接

## 5. 阶段节点
P0 <状态> ｜ P1 <状态> ｜ P2 <状态> ｜ P3 <状态> ｜ P4 <状态>
```

## 六、子 Issue 讨论五项模板（L2 / L3 必填）

| 项 | 必写内容 |
| --- | --- |
| 范围 | 改哪些模块/仓库/流程，明确不改哪些 |
| 契约 | 基于第几版契约，涉及接口、字段、消息或开关 |
| 变更单拆分 | 拆成 1–3 个可独立验收的 PR/MR 及各自验证方式（有叠加依赖写 `Depends-On`） |
| 验收 | 本地测试命令与/或人工冒烟步骤、页面交互引用 |
| 风险 | 开关关闭等于现状说明、存量兼容与回滚方式 |

## 七、L3 升级串与固定标签表

升级 Issue 一事一独立评论串（正文不维护索引表）：
```text
角色 ｜ 槽位 ｜ 会话标识
升级-槽位-NNN ｜ 提出人槽位 ｜ 阻断 / 非阻断
问题：……
影响：……
建议方案：……
建议执行人：……
```
裁决回写（同串追加，写入评论才生效）：
```text
角色 ｜ 槽位 ｜ 会话标识
【裁决】升级-槽位-NNN：结论 ｜ 执行人 ｜ 解除条件：无 / 某变更单合入
```

**固定标签集**（由 `forge.mjs labels-sync --labels ...` 按实际档位同步至全部勾选子仓，默认只补缺不改已有共享标签颜色）：
- L1 必需：`待终审`、`终审中`、`待合并`、`需修改`、`风险高`、`风险低`
- L2 新增：`阻断`、`bug`
- L3 新增：`槽位主研发`、`槽位A`、`槽位B`（按实际槽位数扩展）
