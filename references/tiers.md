# 档位矩阵、唯一阈值表与平滑升档

本文件是 `xxn-lite-loop` **所有档位配置与数字阈值的唯一真相源**，其他文档不得另行定义冲突数值。

## 一、L1 / L2 / L3 三档全景对照

| 维度 | L1 · 极轻档（Sprint） | L2 · 标准档（Standard） | L3 · 团队严格档（Squad） |
| --- | --- | --- | --- |
| **典型场景** | 一句话明确需求、单人 1–2 天独立开发、宽松个人项目 | 个人复杂/多仓需求、长时无人值守（跨夜需显式配置工作时段）、严格工程单人开发 | 2–N 人并行、多仓强耦合核心业务 |
| **Forge 台账结构** | 1 个追踪 Issue（兼台账与子任务清单） | 1 个主台账 Issue + 挂载的业务/bug 子 Issue | `1 + N + 1`：1 总台账 + N 个人小台账 + 1 升级 Issue + 总/子 Issue |
| **契约与归属文件** | 不建 | 多仓接口有变更时仅写简要契约节在台账 | 独立契约文档（P2 冻结）+ 文件归属表/热点文件清单 |
| **运行角色** | 主控（1）+ 子角色（开发/自审）+ 独立终审（一变更单一次新会话） | 主控（1）+ 子角色 + 独立终审 + 静音小巡检（1） | 各槽位主控 + 主研发独立调度 + 独立终审 + 各人静音小巡检 + 全局大巡检 |
| **定时任务** | 默认不建（手动推进） | 主控（30m）+ 静音小巡检（60m） | 各槽位主控（30m）+ 小巡检（60m）+ 主研发调度（30m）+ 大巡检（30m + 可选日报，仅显式启用生成） |
| **起跳阶段** | 直通：一句话确认 → 开发/终审/合入（模糊时走极速 P0） | 可直入 P2/P3，或从 P0/P1 起步 | 标准 P0→P4（自带定稿可直入 P2） |
| **变更单终审** | 必过 1 次独立终审（异厂或更强模型） | 必过独立终审；按 6 条规则判高/低风险 | 全员（含主研发）必过最强模型终审；6 条规则判高/低风险 |
| **需求基线合并** | 默认关（单分支直提主干由本人手合；拆 ≥2 个子 PR 且拉独立需求基线后可开低风险自动合）；严禁自动合入 `main/master/test/uat` | 低风险无依赖可自动合（默认开），高风险本人手合；严禁自动合环境分支 | 仅主研发账号可合基线；低风险无依赖由调度自动合，高风险主研发本人手合 |
| **反复打回熔断** | 同一 PR/MR 累计打回 `k≥2` → 停下交本人拍板 | 同左，强制全量重审后交本人裁决 | 同左，一律换「待合并」列总台账 `[待裁决]` 交主研发裁决 |
| **计划交接换主控** | 单任务结束即拆架，无需换任 | 每完成 1 个业务子 Issue 必换新主控 | 每完成 1 个业务子 Issue 必换新主控 |
| **外部群通知** | 默认关闭 | 可选个人私信 | 可选飞书/外部群：精准真 `@` 涉事人 + 协作者工作时段护栏 + 可选 10:00 日报 |
| **规则维护权限** | 本人随时调整 | 本人随时调整 | 分三级：L1 硬规范与 L2 阶段参数仅主研发走 PR/MR 改；L3 个人配置本人随时改 |

## 二、统一阈值表（仅计工作时段，非工作时段不计）

可在单次需求 `run.json` 的 `thresholds` 字段按需覆盖；未覆盖时一律取下表默认值。

| 阈值项 | 默认值 | 适用档位 | 触发动作 |
| --- | --- | --- | --- |
| `controllerLoopMinutes` | `30` 分钟 | L2 / L3 | 主控与 L3 调度兜底唤醒周期；增量查询重叠 `+10` 分钟 |
| `smallPatrolMinutes` | `60` 分钟 | L2 / L3 | 小巡检周期；无待办无偏离安静退出不刷屏 |
| `leadPatrolMinutes` | `30` 分钟 | L3 | 大巡检变化检测周期；无变化且无到期项安静退出 |
| `dailyReportTime` | `10:00`（本地时区） | L3 可选 | 每日完整兜底并发送 6 段人话日报，按日期幂等去重 |
| `stuckHours` | `2` 小时 | L2 / L3 | 主控「执行中」满 2h：原主控可自愈发【恢复】，小巡检判卡住拉新任 |
| `disconnectCycles` | `2` 个主控周期 | L2 / L3 | 主控空闲且最近唤醒超 2 周期（工作时段满 2 周期起算）：小巡检判失联拉新任 |
| `handoffGraceCycles` | `2` 个主控周期 | L2 / L3 | 判定失联/卡住或交接后 2 周期无新主控接上：巡检催促本人 |
| `confirmTimeoutHours` | `4` 小时 | L2 / L3 | 待确认项满 4 工作小时未回复：小巡检提醒一次 |
| `correctionTimeoutHours` | `2` 小时 | L2 / L3 | 【纠偏】发出满 2 工作小时无「已执行」或「不执行：理由」：巡检跟进 |
| `ledgerMaxLines` | `80` 行 | L2 / L3 | 小台账正文超 80 行或破坏固定章节结构：小巡检发【纠偏】精简并提醒聊控分离；未生效时 L3 大巡检群内提醒 |
| `ledgerStaleWorkdays` | `1` 工作日（8h） | L2 / L3 | 满 1 工作日小台账正文无变化：巡检提醒一次 |
| `mrIdleWarnHours` | `4` 小时 | L2 / L3 | 已建或自审通过 PR/MR 超 4h 未打「待终审」：小巡检提醒本人确认 |
| `mrIdleEscalateHours` | `8` 小时（1 工作日） | L3 | 压单满 1 工作日仍未送审：大巡检群内真 `@` 涉事研发 |
| `p3PauseMaxHours` | `8` 小时（1 工作日） | L3 | P3 阶段某槽位标「暂停」满 1 工作日或暂停期间仍在更新外部文档：大巡检不再豁免，群内真 `@` 涉事人与主研发 |
| `p3SilentMaxHours` | `8` 小时（1 工作日） | L3 | P3 阶段某槽位连续 1 工作日 0 新 PR/MR 且 0 新升级串：大巡检核查子 Issue 五项与外部设计链接并群内真 `@` |
| `reviewStaleHours` | `2` 小时 | L1 / L2 / L3 | 「终审中」超 2h 无结论：由 L1/L2 主控或 L3 主研发调度在每轮扫描时换回「待终审」、评论「超时重派」并派新会话（不算新轮） |
| `reviewWaitWarnHours` | `24` 小时 | L2 / L3 | 「待终审」累计满 24 工作小时（含终审中）：提方主控/小巡检提醒一次（每轮最多 1 次） |
| `blockEscalateHours` | `4` 小时 | L3 | 阻断类升级串满 4 工作小时未裁决：大巡检串内发【提醒】并群通知（超时绝不产生默认裁决） |
| `rejectFuseCount` | `2` 次 | L1 / L2 / L3 | 同一 PR/MR 历史累计打回 `k≥2` 后再送审：强制全量重审，结论后一律交人裁决 |
| `changeGranularity` | `1–3` 个 PR/MR | L2 / L3 | 每个业务子 Issue 按可独立验收功能点拆 1–3 个变更单（拆分角色起草、大巡检复核提醒） |
| `externalMentionWindow` | 协作者工作时段（默认 `09:00–19:00`） | L3 | 大巡检群内真 `@` 协作者的静默护栏；非工作时段发现的提醒暂存到次日工作时段或 10:00 日报发出 |

> **暂停排除口径**：小巡检停滞判定排除个人暂停和非工作时段；L3 的 `P3 长期暂停` 由大巡检按 `p3PauseMaxHours` 单独跟踪，防止暂停黑洞。

## 三、阶段进出条件（L3 完整五阶段，L1/L2 按需直通）

| 阶段 | 核心工作 | 进入下一阶段条件 |
| --- | --- | --- |
| **P0 需求澄清** | 列阻断疑问并完成裁决 | 阻断类疑问全部裁决 |
| **P1 方案设计** | 产出设计、契约初稿、测试验收方案、建首批子 Issue | 方案与契约 v1 确认 |
| **P2 地基与契约** | 主研发交付公共地基，协作者写齐本槽位业务级五项并核对地基契约 | 地基合入基线 + 契约冻结 + 地基验证 |
| **P3 并行开发** | 按子 Issue 细化到代码层 → 本人确认五项 → 小步 PR/MR 终审合入 | 全部业务 PR/MR 合入需求基线 + 集中验证 |
| **P4 联调/测试/上线** | 联调冒烟、缺陷优先闭环、由人合入环境分支部署上线 | 测试结论通过并合入主干 → 执行 `teardown` 拆架 |

阶段切换由本人（L1/L2）或主研发（L3）裁决，定时同步不得代为切换。

## 四、平滑升档协议（顺序迁移，严禁跳档 `L1→L3`）

用 `node <skill>/scripts/loopctl.mjs upgrade --req <slug> --to L2|L3` 生成迁移计划并保留原配置（如自定义主控周期），建好外部 Forge 对象与定时任务并拿到真实台账编号后，再执行 `upgrade --req <slug> --to L2|L3 --apply --issue-map <json> --results <json>` 逐项核对台账与定时任务绑定后落盘（同时将 `contracts` 同步升级为目标档位，外部失败可幂等重试）；`L1→L3` 必须顺序执行 `L1→L2` 再 `L2→L3`。

### 1. `L1 → L2`（个人小活变复杂 / 要跨夜自动推进）

1. **保留资产**：原 L1 追踪 Issue 自动升格为 **L2 主台账**（补齐 5 节快照，历史评论与已合入 PR/MR 链接原样保留）。
2. **新增对象**：把尚未完成的拆分子任务提升为独立业务子 Issue 挂载其下；在所有勾选子仓通过 `forge.mjs labels-sync` 补齐 L2 标签集。
3. **新增会话**：在当前主控会话建立 30m 定时循环 + 另开 1 个独立静音小巡检会话（60m）。
4. **行为切换**：开启低风险自动合并开关、每完 1 个子 Issue 计划交接换新主控、启用 4h 压单提醒与 80 行台账检查。

### 2. `L2 → L3`（单人变多人协作 / 需主研发全局调度）

1. **保留资产**：原 L2 主台账直接升格为 **总台账**（原进度计数与已完成 PR/MR 全部继承），原主控自动转为主研发的个人小台账主控。
2. **新增对象**：
   - 在 `hubRepo` 新建 **本人小台账**（主研发槽位）与 **1 个升级 Issue**；
   - 按需补齐契约与文件归属表（挂总台账第 4 节）；
   - 给未分配的业务子 Issue 打槽位标签（`槽位A`、`槽位B` 等），不预指派账号，等同事接入认领。
3. **新增会话**：
   - 主研发机器另开 **主研发调度**（30m 独立会话，只做派终审合入与同步总台账）；
   - 主研发机器另开 **大巡检**（30m 变化检 + 可选 10:00 群日报）；若启用飞书群真 `@`，必须由发送通知的同一 bot 实查群成员写入 `open_id` 映射。
4. **同事接入**：给同事发总台账链接，同事在本地执行 `$xxn-lite-loop 加入 <总台账链接>` 即可绑定槽位并建起自己的临时主控/小巡检。
